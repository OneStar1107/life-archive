# 01 · 仓库骨架与数据库

> **投喂方式：把 `00-README-总控约束.md` 与本文件一起贴给 AI。**
> 前置：Node.js 20 LTS、pnpm、Docker Desktop 已安装并启动。

---

## ① 角色设定

你是一位**全栈脚手架工程师**，擅长搭建可被多人长期维护、CI 友好、密钥安全的工程骨架。

## ② 目标与上下文

项目 **{应用名称}**（包名 `{包名}`，主体 `{主体名称}`）的第一步：**先把前端和后端分成两个独立顶层文件夹，并把数据库立起来**。这一步不做任何业务功能，只交付可运行、可迁移、可重建的骨架。

核心诉求：后期前端团队和后端团队要能各自独立开发、独立测试、独立部署，所以目录边界必须在第一天就划死。

## ③ 硬约束

- Node.js **20 LTS** + pnpm 9+；包管理器**只用 pnpm**，禁止混用 npm/yarn 产生多份 lock 文件
- PostgreSQL **16**（`postgres:16-alpine`，docker-compose）+ 可选 Redis 7（令牌黑名单/限流）
- Prisma 5/6；迁移文件必须入库
- uni-app x 工程由 **HBuilderX 4.61+** 创建，**VDOM 模式（uts）**
- **项目根路径必须纯 ASCII、无中文、无空格，建议总长 ≤77 字符**（鸿蒙工具链有 255 字符总长限制，否则编译失败或发行后闪退）
- 这是全仓库**唯一一次**允许创建根目录配置文件的阶段；之后新增文件一律落到四个顶层目录内

### `docker-compose.yml` 要点（后端）

```yaml
services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    ports: ["5432:5432"]
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      timeout: 5s
      retries: 10
  redis:
    image: redis:7-alpine
    restart: unless-stopped
    ports: ["6379:6379"]
volumes:
  pgdata:
```

**凭据一律从 `.env` 读取，禁止写死在 compose 文件里**（`${}` 占位即可）。

## ⑥ 分步任务

**T1 · 建立目录骨架**
按 ⑤ 的树创建全部目录与占位文件。同时写根级 `.gitignore`、`.editorconfig`、`README.md`（README 需含：项目简介、技术栈表、本地启动三步命令、目录职责说明、团队约定）。

**T2 · 数据库容器**
写 `backend/docker-compose.yml` 与 `backend/.env.example`。`.env.example` 中每个变量都要有注释说明用途与取值示例，真实值一律留空（并注明该示例值禁止用于生产环境）。

**T3 · Prisma Schema**
`backend/prisma/schema.prisma` 至少包含：
- `User`：id、phone/email、passwordHash、nickname、avatarUrl、status、**createdAt / updatedAt / deletedAt**（软删除）
- `RefreshToken`：id、userId（外键）、tokenHash、familyId、expiresAt、revokedAt、userAgent、ip
- `{业务模块列表}` 中每个模块一个实体，同样带三时间戳
- 统一用 `@map` 映射为下划线表名；所有外键显式写 `onDelete` 策略
- `datasource db` 的 url 从 `env("DATABASE_URL")` 读取

**T4 · 初始迁移**
生成幂等迁移；要求 `pnpm prisma migrate reset` 能完整重建且无数据残留。

**T5 · 种子数据**
`prisma/seed/seed.ts`：管理员账号、字典数据、{业务模块列表} 的演示数据。
**必须支持 `--prod` 开关跳过种子写入**，避免污染生产库；密码必须 bcrypt 加盐，禁止明文或固定硬编码密码进入运行时（seed 里只能是 `$2b$` 开头的哈希或由环境变量注入）。

**T6 · `scripts/bump-version.mjs`**
从 `frontend/version.json` 读取 `{ versionName, versionCode }`，执行后：
1. versionCode **+1 并严格校验大于上一版**（不大于则报错退出）
2. 同步写入 `frontend/manifest.json` 的 Android / iOS / 鸿蒙三处版本节点
3. 同步写入 `frontend/harmony-configs/AppScope/app.json5`
4. 打印 diff 供人工确认

支持 `patch | minor | major` 三种语义。

**T7 · `scripts/check-secrets.mjs`**
正则扫描仓库，命中即 `exit 1`：`.p12` 密码、`JWT_SECRET`、`DATABASE_URL`、AccessKey/SecretKey、Bearer token、`-----BEGIN PRIVATE KEY-----`。同时检查是否有被 git 跟踪的证书后缀文件。

**T8 · 隐私政策初稿**
`docs/privacy/privacy-policy.md`，中文，至少覆盖：收集的个人信息清单（逐项）、每项用途、第三方 SDK 清单（引用 `third-party-sdk-list.md`）、数据存储期限与地域、账号注销与数据导出入口、未成年人保护条款、联系邮箱、政策更新日期。
底部须注明主体 `{主体名称}`。后续部署到 `{隐私政策URL}`。

## ⑦ 代码与命名规范

- TypeScript `strict: true`，`noImplicitAny`、`strictNullChecks` 全开
- Prisma model 名大驼峰单数，表名 `@map` 为复数下划线
- 时间字段统一 `DateTime` + `@default(now())` / `@updatedAt`
- 软删除统一字段名 `deletedAt`，类型 `DateTime?`
- 环境变量经 Joi 校验，缺任一必需项立即 `process.exit(1)`

- [ ] `node scripts/check-secrets.mjs` 输出零告警
- [ ] `node scripts/bump-version.mjs patch` 后：三端 versionName 一致、versionCode 一致且严格递增，并打印出 diff
- [ ] `docs/privacy/privacy-policy.md` 可读且主体正确
- [ ] 根目录除上述配置文件外，**无任何业务源码**

## ⑨ 禁止事项

1. 禁止把 PostgreSQL 数据卷提交进 git
2. 禁止在 `.env` 之外硬编码任何连接串/密钥
3. 禁止 seed 数据进入生产环境（必须有显式开关）
4. 禁止项目路径含中文/空格/emoji
5. 禁止同时存在根目录与 backend 目录下两份 `docker-compose.yml`
6. 禁止用 `prisma db push` 代替迁移（生产不可控）
7. 禁止在 seed 中写入任何真实用户手机号、身份证、邮箱等个人信息
8. 禁止创建一个包含全部业务逻辑的"万能大文件"
