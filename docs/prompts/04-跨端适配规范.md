# 04 · 跨端适配规范（兼容市面上所有手机）

> **投喂方式：`00` + `03`（同批）+ 本文件。**
> 这份解决的是一个具体问题：**中国市面上在售手机的屏幕形态极度碎片化**——从 4.7 寸到 6.9 寸、刘海/灵动岛/挖孔、折叠屏展开态接近平板、还有大量仍在服役的 Android 5~8 老机型。

---

## ① 角色设定

你是一位**移动端 UI 适配专家**，见过太多"在模拟器上完美、在真机上崩版"的案例。你写布局时永远假设：**用户手里那台设备是你从未见过的尺寸**。

## ② 目标与上下文

让 **{应用名称}** 的一套代码在以下六类设备上都不崩版、不遮挡、不裁切：

| 类型 | 典型特征 | 风险点 |
|---|---|---|
| 小屏（≤5"） | 320~375pt 宽 | 元素挤压、按钮重叠 |
| 常规全面屏 | 刘海/挖孔/灵动岛 | 顶部被遮挡、底部被 Home Indicator 压住 |
| 大屏（≥6.7"） | 430pt+ | 内容拉伸留白过多 |
| 折叠屏展开态 | 近似方屏，宽高比接近 1:1 | 锁定方向直接被华为驳回 |
| 平板 / 2in1 | 宽屏 4:3 或 16:10 | 单列拉伸变形，华为明确要求适配 |
| 深色模式 | 系统级反转 | 白底残留、文字不可读 |

## ③ 硬约束

- 布局单位一律 **`rpx`**（设计稿宽度 750）
- **唯一允许使用 `px` 的地方：`1px` 边框**
- 支持的最低系统：iOS 12 / Android 5 / HarmonyOS API 14
- 对比度要求：正文文字与背景 ≥ **4.5:1**
- 最小可点击区域：**88rpx × 88rpx**
- 最小正文字号：**24rpx**

{应用名称}、{核心功能}、{包名}。

## ⑥ 分步任务

### T1 · 设计令牌体系（`tokens.scss`）

必须包含以下类别，**页面禁止出现任何未经令牌定义的字面数值**：

```scss
// 间距（rpx）
$space-xs: 8rpx;  $space-sm: 16rpx;  $space-md: 24rpx;
$space-lg: 32rpx; $space-xl: 48rpx;  $space-xxl: 64rpx;

// 圆角
$radius-sm: 8rpx; $radius-md: 16rpx; $radius-lg: 24rpx; $radius-full: 999rpx;

// 字号
$font-xs: 24rpx; $font-sm: 26rpx; $font-md: 30rpx;
$font-lg: 34rpx; $font-xl: 40rpx; $font-xxl: 48rpx;

// 颜色 —— 必须以 CSS 变量形式定义，支持 dark 覆盖（见 T3）
:root {
  --color-bg: #FFFFFF;
  --color-text-1: #1A1A1A;
  --color-text-2: #666666;
  --color-text-3: #999999;
  --color-primary: #3A7BFF;
  --color-danger: #E54545;
  --color-success: #2FA84F;
  --color-divider: #EEEEEE;
}
```

### T2 · 安全区处理（最容易出错）

**页面级**（`manifest.json`）：已配 `safearea` 的 `background` 与 `backgroundDark`。

**组件级**（`mixins.scss`）——**必须同时写 `constant()` 与 `env()` 两行，缺一不可**：

```scss
@mixin safe-bottom($extra: 0rpx) {
  padding-bottom: calc(#{$extra} + constant(safe-area-inset-bottom));
  padding-bottom: calc(#{$extra} + env(safe-area-inset-bottom));
}

@mixin safe-top($extra: 0rpx) {
  padding-top: calc(#{$extra} + constant(safe-area-inset-top));
  padding-top: calc(#{$extra} + env(safe-area-inset-top));
}
```

> uni-app x 4.52+ 额外提供原生 CSS 变量 `--uni-safe-area-inset-top/bottom/left/right`，**优先使用这些变量**（原生层算得比 web 兼容写法准）。

自定义导航栏（`navigationStyle: "custom"`）时，顶部必须自行补齐 `--status-bar-height`；导航栏高度建议：`calc(var(--status-bar-height) + 88rpx)`。

**固定底栏标准写法**：内容区留出一个占位高度，底栏 `position: fixed` + `@include safe-bottom()`，禁止直接 `bottom: 0`。

### T3 · 深色模式

1. `theme.json` 定义 light / dark 两套变量
2. `pages.json` 中所有颜色用 `@变量名` 引用，**禁止直接写十六进制色值**
3. 图片资源：任何带底色的切图必须提供 `_dark` 变体，或改用纯色/iconfont
4. **启动页与安全区外背景**必须配 `backgroundDark`（最容易遗漏，会露出刺眼白边）
5. webview / 富文本容器需单独注入 dark 样式，否则图文详情会白底黑字反转失败

检查方式：把系统切到深色，**逐个页面截图**，重点看启动过渡、安全区、弹窗、加载态。

### T4 · 折叠屏与平板

- **严禁锁定屏幕方向**（华为审核明确列举"应用强制锁定屏幕方向，不支持系统横竖屏动态切换"为驳回项）
- 布局一律 flex / flex-wrap / 百分比，配合 `min-width` 断点
- 列表在宽屏下自动切双列/三列：以 `uni.getWindowInfo().windowWidth` 判断，**阈值取 600 与 840 两档**
- 折叠态变化监听 `uni.onWindowResize`，页面卸载必须 `uni.offWindowResize`（否则内存泄漏）
- 禁用元素 `width: 750rpx` 撑满后在平板上的拉伸感 → 改用 `max-width` + 居中
- iPad / 平板屏务必单独跑一遍，不要只在手机上验证

### T5 · 系统版本兼容与能力探测

所有高于基线的 API，**调用前必须做能力探测**：

```uts
import { osVersion } from '@/core/platform'

// 示例：仅在支持时使用新能力
if (Number(osVersion()) >= 14) {
  // 使用高版本 API
} else {
  // 降级方案
}
```

- iOS 隐私相关能力（相机/相册/定位/麦克风/蓝牙）必须在 Info.plist 写 `NS*UsageDescription` 文案，且与隐私政策一致
- Android 6+ 需运行时动态申请危险权限；鸿蒙需 `requestPermissions` + 运行时 `requestPermission`
- 鸿蒙 API 版本探测：`uni.getDeviceInfoSync().osHarmonySDKAPIVersion`

### T6 · 条件编译矩阵（唯一合法的差异写法）

| 场景 | 正确写法 |
|---|---|
| 编译期分支 | `// #ifdef APP-HARMONY` / `// #ifdef APP-ANDROID` / `// #ifdef APP-IOS` … `// #endif` |
| 运行时判系统 | `uni.getDeviceInfoSync().osName` → `'harmony' \| 'ios' \| 'android'` |
| 运行时判平台 | `uni.getSystemInfoSync().platform` → `'harmonyos' \| 'ios' \| 'android'` |
| 鸿蒙 API 版本 | `uni.getDeviceInfoSync().osHarmonySDKAPIVersion` |

> **写错成 `HARMONYOS` 是最高频事故**——编译不生效但不报错，安卓专属 API 被打进鸿蒙包，运行即崩。

### T7 · 文本与字体

- 最小字号 24rpx
- 支持系统字体缩放：容器**禁止** `overflow: hidden` 硬裁文字，长文案须换行或省略（`text-overflow: ellipsis`）
- 中英混排注意行高，统一用 `$line-height` 令牌（建议 1.5）
- 数字、金额用等宽对齐，避免列表跳动

### T8 · 图片与资源

- 图标**优先使用 iconfont 或 SVG**，避免多套位图
- 位图至少提供 2x/3x 两档，或用矢量方案彻底规避
- 列表图片必须设 `mode="aspectFill"` 并固定容器宽高比，避免加载完成后布局跳动

## ⑦ 代码与命名规范

- SCSS 变量命名：`$类别-尺寸`
- CSS 变量（支持 dark 覆盖）命名：`--类别-用途`
- mixin 命名：动词短语（`safe-bottom` / `text-ellipsis` / `respond-to`）
- 每个组件 `<style scoped>` 内禁止出现颜色或尺寸字面量（除 `1px`）

在以下六类设备上**逐个截图确认**，附在产出中：

- [ ] 小屏（≤5"）：无挤压、按钮不重叠、文字不裁切
- [ ] 刘海/灵动岛/挖孔机型：顶部内容不被遮挡
- [ ] 全面屏底部：悬浮按钮与 tabBar 不被 Home Indicator 压住
- [ ] 大屏：无异常留白、无拉伸变形
- [ ] 折叠屏展开态：布局自适应，无锁方向，**展开/折叠切换不崩溃**
- [ ] 平板/宽屏：列表自动多列，单列内容有 max-width 约束
- [ ] 深色模式：无白块、无不可读文字，对比度 ≥ 4.5:1
- [ ] 横竖屏连续切换 10 次：不崩、不锁死、不错位
- [ ] `grep -rn "100vh\|375px\|667px" --include="*.uvue" frontend/` 返回空
- [ ] `grep -rn "#ifdef" frontend/pages frontend/components` 返回空
- [ ] 系统字体调到最大后，主要页面文字不被截断

## ⑨ 禁止事项

1. 禁止硬编码宽高、屏幕像素值、`100vh`
2. 禁止 `position: fixed; bottom: 0` 而不加安全区
3. 禁止锁定 `orientation`
4. 禁止用 Android 权限名写鸿蒙代码
5. 禁止假设所有设备同一分辨率或同一宽高比
6. 禁止在 `pages.json` 里直接写十六进制色值
7. 禁止忘记 `offWindowResize` 导致监听泄漏
8. 禁止使用低于兼容基线的系统 API 而不做能力探测
9. 禁止只在手机尺寸上验证就宣称"适配完成"
10. 禁止用图片承载本可用 CSS 实现的纯色背景或圆角
