# 三端 App AI 提示词包 · 使用说明

一套用于驱动 AI 编码代理**从零构建并上架**跨端联网 App 的提示词。

覆盖：**iOS + Android + HarmonyOS NEXT** 三端开发 → 测试 → 真机安装 → 应用市场上架。

## 一、先填占位符（只做一次）

打开 `00-README-总控约束.md`，把文件顶部的「用户填写区」表格替换成真实值，然后**把这些值同步到所有文件**（全局替换即可）：

| 占位符 | 含义 | 特别注意 |
|---|---|---|
| `{应用名称}` | 中文市场名 / 桌面名 | **必须与软著名、APP 备案名、商店名一字不差** |
| `{应用英文名}` | 英文或拼音名 | 用于 bundleName 末段 |
| `{包名}` | 三端统一包名 | ≥3 段、7~128 字符、禁含 `oh/ohos/harmony/openharmony/system` 独立段 |
| `{核心功能}` | 一句话业务描述 | |
| `{业务模块列表}` | 逗号分隔的领域模块 | 决定前后端模块划分 |
| `{API域名}` | 后端 HTTPS 域名 | 须已 ICP 备案 |
| `{隐私政策URL}` | 隐私政策网页 | 必须是独立可访问网页 |
| `{主体名称}` | 营业执照主体全称 | 软著/备案/开发者账号必须同一主体 |
| `{目标市场}` | `android-domestic` / `google-play` / `ios` / `harmony` | 决定 08 投喂哪一章 |
| `{合规等级}` | `basic` / `finance` / `health` / `news` / `ugc` / `ai-gen` | 决定资质清单 |

> 填不动？先用临时值跑通流程，**但 `{应用名称}` 一旦确定了就别再改**——改名字等于软著、备案、商店全部重来。

## 四、三条最贵的教训

### 1. 鸿蒙没有云打包
Android 和 iOS 可以在 HBuilderX 里云打包（Windows 也能出 iOS 的 ipa），**鸿蒙不行**——必须本地装 DevEco Studio 出 `.app`，用 `hdc install -r` 安装，不是 adb。这点不知道会白白浪费两天。

### 2. 平台宏是 `APP-HARMONY`，不是 `HARMONYOS`
写错了**不报错**，但编译不生效，安卓专属 API 会被打进鸿蒙包，运行即崩。所有平台差异必须收敛在 `frontend/core/platform/index.ts`，禁止散落到业务代码。

### 3. 上架是证件活，不是技术活
软著（约 30 工作日）+ ICP 备案（7~20 工作日）+ APP 备案（7~20 工作日）加起来可能两个月。**开发第一天就要并行启动**，否则代码写完了只能干等。

## 五、常见问题

**Q：能不能跳过 01，直接写业务功能？**
不建议。01 建立的目录边界、`.gitignore`、版本脚本是后期不返工的前提。尤其 `.gitignore` —— 证书一旦提交上去，整个仓库历史都得重写。

**Q：我只上架 iOS，08 号怎么投喂？**
把 `{目标市场}` 填 `ios`，然后删掉 A 章和 C 章，只留 D 章 + B 章。**D 章不能删**，APP 备案和隐私政策三端通用。

**Q：AI 写出来的代码编译不过怎么办？**
把完整报错贴回去，并附加一句：「对照 00 号第 ⑥ 节的八个高频坑逐条排查」。绝大多数编译失败来自第 1、2、5 条（平台宏、硬编码尺寸、鸿蒙权限）。

**Q：能换成 Vue3 版本的 uni-app（不是 uni-app x）吗？**
可以，但需要重写 03、04 号。注意：老 uni-app 的 App 平台官方将于 2027 年初停止维护；且它用 jsvm，在某些 CPU 的鸿蒙模拟器上受限。

**Q：蒸汽模式（js/ts，能用 npm）会更好吗？**
要看你的版本基线能不能接受 iOS 15+ / Android 6+ / 鸿蒙 API 20。若能，蒸汽模式性能和开发体验都更好；若必须覆盖老机型，就用 VDOM。本套提示词默认 VDOM。
