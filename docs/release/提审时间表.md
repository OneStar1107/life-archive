# 提审时间表

> **本文件的用途**
> 本文件是「人生档案」（`com.lifearchive.app`）三端上架的**倒排时间表**（T-60 → T+5），把证件、测试、材料、提审四类工作按依赖关系排开。
>
> 依据 `docs/prompts/08-三端上架发布.md` 第 ⑩ 节输出格式要求第 2 条：
> > 倒排时间表：软著办理（T-60 天）→ ICP 备案（T-45 天）→ APP 备案（T-30 天）→ 测试（T-15 天）→ 三端提审（T-0）
>
> **什么时候填**
> 1. **T-0 定下来之后**，把所有绝对日期填进「起止」两列。
> 2. 每次某一项完成后，在「状态」列打勾并记录实际完成日。
> 3. 有延期时立刻更新「风险」列并调整后续依赖。

## 三、关键路径

> 路径中的每一项延迟一天，提审日就延迟一天。

```
D1 营业执照 (T-60 → T-50, 源头上游)
  │
  ├─→ D2 软著 (T-60 → T-30, 30 工作日, 最长单项工作)
  │     │
  │     └─→ D4 APP 备案 (T-30 → T-10, 7~20 工作日) ──┐
  │                                                    │
  └─→ D3 ICP 备案 (T-45 → T-25, 7~20 工作日) ────────┤
       │                                             │
       └─→ D5 隐私政策网页部署 (T-45 → T-20) ─────────┤
                                                     │
  三端签名证书 (T-40 → T-35) ────────────────────────┤
                                                     │
  阶段 06 三端出包 ──→ T-15 真机测试 ──→ T-7 材料 ────┼─→ T-0 提审
                                                     │
                                    ★ T-0 提审日 ◀───┘
```

**⚠️ 关键路径分析**

1. **最长的单项工作是 D2 软著（30 工作日）**，且它还阻塞 D4 APP 备案。
2. **D3 ICP 备案与 D2 软著可以并行**（都只依赖 D1），这是唯一能压缩总时长的手段。
3. **T-0 提审的硬前置是 D4 APP 备案通过**。若 D4 在 T-10 才过，**T-0 必须顺延**。
4. **技术侧最长链路是「阶段 06 出包 → T-15 测试」**，若出包晚于 T-15，测试窗口被压缩，风险陡增。

## 四、缓冲与回退

| 场景 | 影响 | 应对 |
|---|---|---|
| D2 软著被驳回（名称不符 / 材料问题） | 30 工作件重来，提审顺延一个月 | 提交前**逐字核对名称为「人生档案」**；保留驳回记录与补正说明 |
| D3 ICP 备案被退回 | D5 无法部署，隐私政策 URL 不可用 → **禁止提审** | 主体材料先自查；域名先完成实名 |
| D4 APP 备案被退回 | **商店拒绝收录** | 名称/包名/主体/备案类型四项自查；⚠️ 华为备案刚过需等 1 工作日 |
| 鸿蒙发布证书丢失 | 无法出包 | 备份策略见 [`signing-ledger.md`](./signing-ledger.md) 第六节；⚠️ 每账号仅 1 个发布证书 |
| 阶段 06 出包延期 | 测试窗口压缩 | 优先保证**鸿蒙 + Android**（Android 六市场量最大），iOS 可错峰 |
| 审核驳回 | 顺延 1~3 工作日/轮 | 记录驳回原因到 [`上架台账.md`](./上架台账.md) 第 4 节，**同类问题不要犯第二次** |
| 三端不必同日提审 | — | ✅ **强烈建议**：鸿蒙审核最快（24h 内），可先提鸿蒙；安卓六市场可分批；iOS 排最后（备案编号依赖最多） |
