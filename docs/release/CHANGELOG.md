# 版本变更记录

> **本文件的用途**
> 本文件记录「人生档案」（`com.lifearchive.app`）每一个对外发布版本的变更内容，供商店审核说明、用户查阅与问题回溯使用。
>
> **与 PRD 的分工（2026-10-25 起）**
> **条目级变更（问题 / 规则 / 状态 / 落点）只记在 [`docs/prd.md`](../prd.md)，本文件不重复。**
> 本文件只写「这个版本对外改了什么」——发版时从 PRD 的变更记录汇总成用户看得懂的一句话。
>
> **什么时候填**
> 1. **发布前**：在「待发布」区写好这一版改了什么。
> 2. **发布当天**：把「待发布」移到顶部表格，填发布日期与各市场审核状态。
> 3. 每次版本号递增（`node scripts/bump-version.mjs`）后**必须**回填本文件。

---

## 格式约定

本项目采用 **Conventional Commits** 规范撰写 commit message，本文件的变更条目与之保持一致。

### 1. Commit Message 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 2. type 类型

| type | 含义 | 用在哪 |
|---|---|---|
| `feat` | 新功能 | 新增业务能力 |
| `fix` | 缺陷修复 | 修 bug |
| `perf` | 性能优化 | 启动速度、渲染、内存 |
| `refactor` | 重构 | 不改变外部行为的内部调整 |
| `style` | 代码格式 | 缩进、命名、分号（**不改业务逻辑**） |
| `docs` | 文档 | 只改文档 |
| `test` | 测试 | 新增或修改测试 |
| `build` | 构建 | 版本号、依赖、构建脚本 |
| `ci` | CI 配置 | 流水线 |
| `chore` | 杂项 | 脚手架、配置文件 |
| `revert` | 回滚 | 撤销某次提交 |

### 3. scope 范围

| scope | 含义 |
|---|---|
| `auth` | 登录 / 注册 / 令牌（`backend/src/modules/auth`） |
| `users` | 账号资料 / 导出 / 注销（`users`） |
| `profiles` | 基本资料 / 边界设置（`profiles`） |
| `feelings` | 感受记录（`feelings`） |
| `memories` | 记忆图谱 / 时间轴 / 关系（`memories`） |
| `health` | 身体信号（`health`） |
| `journeys` | 旅途（`journeys`） |
| `todos` | 待办（`todos`） |
| `insights` | 洞察（`insights`） |
| `files` | 文件上传（`files`） |
| `harmony` | 鸿蒙端适配与出包 |
| `android` | 安卓端适配与出包 |
| `ios` | iOS 端适配与出包 |
| `privacy` | 隐私政策 / 权限 / 合规 |
| `release` | 发布相关（版本号、签名、素材） |
| `docs` | 文档 |

### 4. subject 规范

- 使用**中文**，以动词开头
- 结尾**不加句号**
- 长度 ≤ 50 字符
- 破坏性变更用 `!` 标注并加 `BREAKING CHANGE:` footer

### 5. 示例

```
feat(feelings): 新增情绪粒度标签与情绪统计接口

- 支持为单条感受添加多个标签
- 新增 /feelings/daily-stat 聚合接口
- 情绪趋势支持按关键词与时间范围过滤

BREAKING CHANGE: /feelings 的响应结构新增 refinedLabel 字段，
旧版客户端需升级才能正确渲染。
```

### 技术与合规要点

| 项 | 内容 |
|---|---|
| 包名 | `com.lifearchive.app`（三端统一） |
| 版本 | `versionName 1.0.0` / `versionCode 100` |
| 渲染模式 | uni-app x VDOM |
| 第三方 SDK | **0 个**（VDOM 模式不支持 npm 引入第三方包） |
| 权限 | 鸿蒙 3 条（`INTERNET` / `GET_NETWORK_INFO` / `WRITE_DOWNLOAD_DIR`）；Android 2 条；iOS 0 条 |
| 隐私同意 | `privacy_consent_accepted`，首启弹窗，**未同意前不采集任何信息** |
| 密码存储 | bcrypt 加盐哈希（cost 12），**无法看到明文** |
| 健康数据 | **用户手动录入**，**不接入系统健康平台** |
| 位置 | **不申请定位权限**，旅途坐标由用户手动填写 |
| 洞察生成 | **确定性规则**本地计算，**不接入大语言模型** |
| 数据删除 | 注销后**软删**立即不可见，**15 日内**物理删除 |

## 版本号规则

### 语义化版本

```
主版本号.次版本号.修订号
  1      .  0    .   0
```

| 位 | 何时递增 | 示例 |
|---|---|---|
| 主版本号 | **不兼容的 API 变更**、数据结构重写、账号体系变更 | `1.0.0` → `2.0.0` |
| 次版本号 | **向后兼容的新功能** | `1.0.0` → `1.1.0` |
| 修订号 | **向后兼容的缺陷修复** | `1.0.0` → `1.0.1` |

### versionCode 规则

> ⚠️ **`versionCode` 严格递增，这是华为与 Google Play 的明确驳回项。**
> ⚠️ **只改 `versionName` 不改 `versionCode` 会被驳回。**

| 变化 | `versionName` | `versionCode` |
|---|---|---|
| `major` | `1.0.0` → `2.0.0` | `100` → `200` |
| `minor` | `1.0.0` → `1.1.0` | `100` → `110` |
| `patch` | `1.0.0` → `1.0.1` | `100` → `101` |

### 唯一源与同步

- **唯一源**：`frontend/version.json`
- **同步工具**：`node scripts/bump-version.mjs <patch|minor|major>`
- **禁止**手改 `frontend/manifest.json` 与 `frontend/harmony-configs/`
- 递增后**必须**核验：Android / iOS / 鸿蒙三端 `versionName` 与 `versionCode` 均一致

### 商店提交前必查

- [ ] `versionCode` **严格大于**上一版已提交的 versionCode
- [ ] 三端 `versionName` / `versionCode` 完全一致
- [ ] 本文件已回填该版本的变更摘要与发布日期
- [ ] [`上架台账.md`](./上架台账.md) 第 5.2 节版本记录表已更新
